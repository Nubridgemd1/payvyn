SOC 2 ReadinessScope, Trust Services Criteria, controls & roadmap to attestation
Important: a SOC 2 report can only be issued by an independent licensed CPA firm after an examination. This is a readiness package — it defines the scope, criteria, and controls so an auditor can be engaged. It is not a SOC 2 report or attestation.
Target: SOC 2 Type II — Security (plus Confidentiality), the categories FI partners request for a vendor handling NPI. This package maps Payvyn's controls to the AICPA Trust Services Criteria and sets the path to an attestation.

1Scope & system description

  • System: the Payvyn onboarding application, verification backend (identity pre-screen, OFAC, bank verification, NACHA generation), data stores, and supporting cloud infrastructure.
  • Trust Services Categories: Security (Common Criteria) and Confidentiality. [Add Availability if partners require an uptime commitment.]
  • Boundaries / subservice organizations: cloud/infrastructure providers (carve-out method), covered by complementary subservice-organization controls.

3Evidence Payvyn can already show

  • Encryption in transit (TLS) and at rest (AES-GCM); full SSN/account numbers server-side only.
  • Access control & least privilege; secrets in a managed secret store; verification attempt-limiting.
  • Change-managed deployments; the GLBA WISP; data inventory & retention schedule.

4Gaps to close before the audit (assign owners + dates)

  • Formalize policies (IR plan, access, change, risk-assessment, vendor) and get them approved.
  • Stand up continuous monitoring / evidence collection (a SOC 2 automation platform helps).
  • Schedule and complete a third-party penetration test and vulnerability scanning cadence.
  • Document subprocessors + collect their SOC reports; sign DPAs.
  • Security-awareness training records; background-check process.
